## 2. 工作流程（本仓库固定用法）

superpowers 的 **subagent-driven-development（SDD）**，逐任务闭环：

```
写 brief（<workspace>/task-N-brief.md）
→ 实现者 TDD：写失败测试 → 跑到失败 → 实现 → 跑到通过 → 提交 → 自审 → 写 task-N-report.md
→ 控制器出 review package（git log/diff 重定向到文件：review-task-N.md）
→ 任务复核（独立子代理；**若用户要求「自己干」，则控制器本人复核并如实记录独立性变弱**）
→ 有 Critical/Important → 修复轮 → 复审通过
→ 下一个任务
→ 全部完成后：一次全分支复核 → 收尾
```

**本会话的用户约束**：`自己干，不准派子智能体` —— 控制器同时是执行者与复核者，**独立性弱于正常流程**，必须在报告与 ledger 里如实写明（T1–T5 都这么做了）。
**实际偏差（记在 ledger 里免得下一会话以为漏了）**：T2 起没有单独写 `task-N-brief.md`，任务要点直接落在 `task-N-report.md` 里。

## 5. 必须继承的「坑」与裁决（不读会重犯）

- **客户端接缝仍是未验证假设**，1c 才能真机验证；所有接缝只在 `src/client/shell.ts` 与 `src/client/seams.ts` 两层，1c 只改这两层。
- **cordis 的 `Service` 实例对外是代理**：`#` 私有成员会抛 `TypeError: Receiver must be an instance of class …`；服务里一律用 TS `private`。
- **cordis 的服务解析只向上找**：共享服务必须注册在 `ctx.root`；`ctx.set` 之前必须 `ctx.provide`。
- **宿主提供的包必须保持外部**：`@deepseek-ai/dsh-typert-protocol` 曾在 `devDependencies` 被内联 → 已进 `peerDependencies` + `neverBundle`，构建测试断言「整目录里至少有一个产物仍裸导入它」。
- **客户端产物护栏**：`lib/client.js` 自包含（不相对引用分块）、裸导入只在宿主白名单（`react` 等）、`node:` 命中 0。
- **能力矩阵的唯一来源在宿主侧**（Ruling 28），经 `status().capabilities` 发布；**不要在客户端再抄一份**。
- **账户卡片是受控组件**（Ruling 29）：草稿住 `page-state.ts`；**密钥输入不带 `data-field`**（那是设置字段的通道）；空名称/空密钥不提交。
- **登录撞名判定**（Ruling 30）：`loginSlotHolder(views, ref, userName)` —— 只有明显同名才允许覆盖凭据槽；不同名一律拒绝（可读错误 `credential-slot-taken`）。`storeKey` 的第三个参数就是登录用户名。
- **厂商识别**：靠设置命名空间发现（Ruling 2）；**opencode 的宿主行 id（`opencode-go`）与核心命名空间（`llm-opencode-go`）不同**，注册表用 `rowIds` 两个都列（Ruling 25）。
- **`unavailable` 不产出切换提示、不编造原因**（Ruling 17）；**额度读数归属必须显式给出**（Ruling 19）。
- **排序是上移/下移，不是拖动**（Ruling 31）：本期没有 DOM，拖动既写不出可信实现也测不了；`moveAccount(ref, toIndex)` 的 `toIndex` 是**移动后的最终下标**。
- **模型卡片的模型来源是设置文档**（Ruling 32）：列出「白名单 ∪ 显隐表里出现过的模型」，用户手动加 id；**没有实时目录**（远程面没发布目录）。
- **`applyModelEdit` 的 id 必须先 trim**：白名单与显隐键必须是同一个 id（测试抓出过键没 trim 的真 bug）。
- **`VendorEntry` 的三个可选声明**（`rowIds`/`cards`/`models`）都是「这家支持什么」的唯一来源（Ruling 25/28/33）：缺席 = 不渲染/不发现。**不要在客户端别处再判一遍**。
- **意图日志的重放仍未接线**（1c 要加崩溃重放演练）。
